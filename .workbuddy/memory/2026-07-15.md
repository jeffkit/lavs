## LAVS `mcp` handler 执行器补齐（同日 part 2）

用户："剩下什么能做的你就继续做一下" → 补完 `mcp` handler（原 STATUS 标注 TODO 的项）。

### 代码改动（TS runtime）
- 新增 `src/mcp-executor.ts`（`McpExecutor`：*forward* MCP bridge）。
  - 从 `context.workdir` 读 `mcp-config.json`（连接配置独立于 lavs.json，符合 SPEC 9.3）。
  - 构建 transport：`stdio`(`StdioClientTransport`) / `http`(`StreamableHTTPClientTransport`)。
  - 连 `Client` → `callTool` → 结果提取：优先 `structuredContent`，否则 text 段 `JSON.parse` 回退文本。
  - 错误映射：`isError` → `HandlerError`；超时（`context.timeout ?? serverCfg.timeout ?? 30s`）→ `Timeout`，用 `withTimeout` 包装 connect+call。
- 三处类型加 `McpServerConfig`/`McpConfigFile`（runtime/types/client）。
- `tool-generator.ts` switch 加 `case 'mcp'`（接 `McpExecutor`）；`index.ts` 导出。
- `cli.ts` 的 `validate` 增强：若存在 `mcp-config.json` 也做轻量结构校验（transport 合法、stdio 需 command、http 需 url），失败退出码 1。

### 测试
- 新增 `src/mcp-executor.test.ts`（5 个）：stdio 调用返回 structuredContent、tool isError→HandlerError、server 缺失→HandlerError、mcp-config 缺失→HandlerError、慢 tool→Timeout。
  - 配套 fixture `src/__fixtures__/echo-mcp-server.mjs`（最小 MCP stdio server，echo/boom/slow 三工具）。
- `tool-generator.test.ts`：把原"mcp 抛 not supported"用例改为 mcp 经 generator 端到端成功 + 新增"未知 handler type 被 loader 拒绝"。
- 全量 **155 测试通过**（原 149 → +6），`tsc --noEmit` 干净。
- 手测 `lavs-runtime validate`：合法 mcp-config 退出 0、非法（stdio 缺 command）退出 1 并报清晰错误。
